# Guided Course Website Build Rules

Use these rules whenever creating or substantially revising an Industrial Technology guided-course website.

## Responsibilities

- **ChatGPT in the in-app browser** writes all new teaching theory and generates any new project visuals, diagrams and folio infographics.
- Ask ChatGPT for **one theory section at a time**, using a precise module title, student level, workshop context and word range. Do not ask it to write a whole course in one prompt.
- **Codex** integrates the exact approved ChatGPT output, connects it to the website, tests the student experience, preserves existing files and publishes only when the full change is ready.
- Use the project’s existing image folders first. When a new visual is needed, give ChatGPT the actual project reference image and a precise brief. Never substitute a generic product image for the project being built.

## Teaching and student flow

- Every two-week module is a complete student package: three substantial theory sections, relevant visuals where they aid understanding, multiple-choice knowledge checks, scaffolded written responses with feedback and model responses, student details, autosave and Print / Save PDF evidence.
- Questions, hints and written-response scaffolds must match the theory students have just read. Remove obsolete, repeated or confusing content.
- Keep the quality, clarity and length comparable to the Folding Chair guided course, while lifting content for the appropriate project and syllabus level.
- Check the original project repository, plans and syllabus mapping so an improved layout does not lose required content or outcomes.

## Design and publishing

- Treat Folding Chair, Mirror, Bedside Table and later courses as sister sites: common landing-page rhythm, typography, card scale, navigation, evidence notice, resources, visible syllabus/outcomes section and footer; project-specific content and imagery.
- Keep each project’s visual reference accurate. Generated images and infographics must show the actual project style, materials and construction details.
- Build and test locally first. Test the landing page, every module, questions, written responses, PDF output, plans and folio before committing and publishing.
- Report plainly whether a change is local only, pushed to GitHub, or confirmed live on GitHub Pages.
